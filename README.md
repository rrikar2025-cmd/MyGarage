# Мій гараж / My Garage

Робоча версія 0.4.0 нового застосунку, створена окремо від DriveSpecX-RN.
React Native 0.81.5, Expo SDK 54, TypeScript, Expo Router, Zustand, Supabase. SDK 54 збережено навмисно для сумісності перенесеного OBD-модуля; оновлення SDK — окремий етап після перевірки на телефоні.

## Що вже працює

- Українська й англійська; світла, темна та системна тема.
- Автомобілі: марка, модель, рік, пробіг, номерний знак, VIN; створення, редагування, вибір, видалення.
- Заправки: дата, пробіг, літри, вартість, тип пального, повний бак і розрахункова ціна літра.
- Сервіс: роботи, категорія, дата, пробіг, вартість, нотатки, наступний сервіс за датою та/або пробігом; окремий екран термінів.
- Звіти витрат за вибраний місяць/рік, останні 30 днів і 12 місяців; графік, окремі суми пального/сервісу та CSV. Підсумки використовують усі фінансові записи.
- Витрата л/100 км за повними заправками: базову заправку не враховано, проміжні враховано, різні типи пального та невідомі дані не змішуються.
- Локальний гостьовий гараж; окремі хмарні дані після входу.
- Вхід/реєстрація, повторний лист підтвердження, відновлення пароля через PKCE-посилання, встановлення нового пароля й видалення власного акаунту з повторною автентифікацією. Реальна доставка пошти й повний цикл на телефоні ще потребують ручної перевірки.
- Supabase email/password Auth та репозиторії для авто, діагностики, заправок, сервісу; SQL-схема з RLS, перевірена локально.
- Перенесений iOS/Android BLE ELM327 модуль, CAN DTC decoder, серіалізовані операції, пошук адаптерів, запити stored/pending/permanent кодів, телеметрія. Реальний зв’язок з авто ще потрібно перевірити на телефоні.

Це не повне перенесення DriveSpecX. Повний перелік функцій та черговість перенесення — у ROADMAP.md.

## Запуск

Залежності вже встановлено. Для нового клонування потрібен Node.js >=20.19.4:

```bash
cd /Users/a/Desktop/MyGarage
npm ci
```

Для перегляду інтерфейсу:

```bash
npm run web
```

Або без Metro/watcher, з готової веб-збірки:

```bash
npm run export:web
npm run preview
```

Відкрити http://localhost:8082. Перегляд ширини телефона: http://localhost:8082/__preview/mobile?width=390 (також 320 або 430). Тестові записи додаються лише у сховище браузера; у вихідному коді немає seed-автомобіля.

Для діагностики потрібна нативна development-збірка. Expo Go та браузер можуть показати інтерфейс, але не мають цього власного Bluetooth-модуля:

```bash
npm run ios
# або
npm run android
```

Після встановлення development-збірки:

```bash
npm start
```

Нативні каталоги генеруються з app.config.ts і plugins/. Вони не переносяться зі старого проєкту. Не редагуйте згенеровані налаштування вручну: зберігайте зміни в Expo config plugin.

## Supabase

Поточний чистий проєкт `MyGgarage` підключено через локальний `.env`. Міграції 001–004 застосовано 2026-10-28 через SQL Editor; ізоляцію двох власників перевірено на живій базі у транзакції з ROLLBACK. Клієнтська збірка додатково перевіряє, що налаштування з `.env` фактично потрапили в bundle. Паролі та ключі не записувалися в документацію.

Деталі й стан migration history: `supabase/DEPLOYMENT.md`. Не запускайте початкову схему повторно на вже налаштованій базі.

Без .env застосунок явно працює у локальному режимі. Жодних реквізитів старого Firebase чи іншого Supabase-проєкту не скопійовано.

Для нового клонування з іншою базою:

1. Створити окремий Supabase-проєкт для My Garage.
2. Застосувати усі чотири файли з supabase/migrations/ у порядку назв у цьому новому проєкті.
3. Скопіювати .env.example у .env і вказати Project URL та publishable key. Це публічні клієнтські параметри; ніколи не використовуйте service_role ключ у застосунку.
4. Увімкнути email/password і підтвердження пошти; налаштувати сайт/лист підтвердження у Supabase Auth.
5. Перезапустити Expo. У налаштуваннях стане доступний вхід.

Гостьові дані не завантажуються в акаунт автоматично. Native auth-сесія зберігається через SecureStore; браузерна — у локальному сховищі. RLS обмежує кожну таблицю власником; composite foreign key не дозволяє прив’язати власний запис до чужого авто. SQL-тести використовують окремий PostgreSQL-сумісний рушій PGlite, не реальний Supabase акаунт.

## Архітектура

```text
app/                 тонкі маршрути Expo Router
src/app/             providers, навігація та ініціалізація
src/pages/           композиція екранів
src/widgets/         перевикористовувані великі блоки: підсумки витрат
src/features/        підключення адаптера, сканування, авторизація
src/entities/        garage (агрегат авто/історії), obd, session
src/shared/          UI, теми, i18n, API-клієнт, інфраструктура
modules/obd/         перенесений нативний Expo-модуль Swift/Kotlin
supabase/            міграція й локальна конфігурація
```

FSD імпорти спрямовані вниз; slices мають index.ts. Garage є єдиним агрегатом, бо записи володіють життєвим циклом авто й разом видаляються. Немає залежностей між slices одного шару. Expo Router root явно заданий як ./app, щоб src/app/ із FSD не інтерпретувався як маршрути.

## Android APK

Перенесено механізм версій зі старого застосунку й адаптовано назву:

```bash
npm run android:release
```

Очікуваний формат: MyGarage-0.4.0(2)-release.apk. Номер з app-version.json збільшується лише після успішної збірки й наявності APK. Це локальний артефакт для перевірки, не публікація в Google Play. Production signing, остаточні app identifiers та EAS-проєкт потрібно налаштувати перед релізом. Нічого в стори не завантажено.

## Звіти й витрата палива

З огляду або щоденника натисніть «Детальний звіт». Місяць/рік можна змінювати стрілками; останні 30 днів включають сьогодні й попередні 29 календарних днів. Останні 12 місяців — від дня після відповідної дати минулого року до сьогодні; 29 лютого коректно враховано. Звіти завжди стосуються обраного авто.

CSV у браузері завантажується як файл, на iOS/Android відкриває системне меню поширення. Файл містить лише записи поточного періоду й авто. Формули з введених користувачем рядків нейтралізуються, Unicode/переноси рядків зберігаються. Збереження або відправлення з системного меню обирає сам користувач. Додано expo-file-system і expo-sharing — попередню нативну development-збірку треба перевстановити.

Для л/100 км запишіть усі заправки, вкажіть тип пального й позначайте справді повний бак. Рахуються завершені цикли «повний → повний», включно з проміжними заправками. У звіт потрапляють цикли, що завершилися в ньому; початок може бути раніше. Середнє зважене за пробігом, а не середнє арифметичне окремих показників. Зміна типу пального, невідомі метадані або зменшення пробігу розривають цикл. Пропущені користувачем заправки неможливо виявити автоматично.

Сервіс настає за датою або пробігом, що буде раніше. Останній запис категорії замінює її попередній термін; роботи категорії «Інше» розрізняються за назвою. Зелений/червоний статус завжди має текст. Push-нагадування ще не реалізовані.

Після зміни `.env` використовуйте `npm run export:web -- --clear`. `postexport:web` перевіряє відсутність застарілих налаштувань у готовій веб-збірці й не друкує ключі.

## Акаунт — 0.3.0

Повернення з листів: `/auth/callback` для поточного web origin або `mygarage://auth/callback` для development build. Supabase використовує PKCE; відкривайте лист у тому самому браузері/застосунку, де надіслали запит. Посилання потребує явного натискання «Підтвердити посилання». Коди з адреси прибираються й залишаються лише в оперативній пам’яті. Старі implicit-посилання з access/refresh token не приймаються: надішліть новий лист. Після перезапуску/оновлення сторінки відновлення потрібне нове посилання. За кількох запитів використовуйте найновіший лист.

Без потрібних криптографічних примітивів запити PKCE не надсилаються: web підкаже відкрити HTTPS/localhost або нативний застосунок. На Hermes відсутні WebCrypto-примітиви для PKCE підключаються через expo-crypto (безпечний random і SHA-256), браузер використовує власний WebCrypto. Цю платформну гілку ще потрібно перевірити в нативній development-збірці.

«Налаштування → Безпека акаунту → Видалити акаунт» показує конкретну пошту, перелік даних, поле поточного пароля й слово ВИДАЛИТИ / DELETE, а потім окремий фінальний діалог. Сервер вимагає збіг поточного користувача з підтвердженим, живу auth.sessions-сесію та password AMR не старіший за 5 хвилин. Каскадно видаляються користувач, його сесії й усі поточні таблиці гаража. Гостьове сховище залишається окремим. При додаванні Storage/нових таблиць необхідно розширити життєвий цикл очищення; серверна помилка не вважається успішним видаленням.

Supabase має налаштовані native/localhost callback URLs і development Site URL http://localhost:8082. Перед релізом потрібні справжній production URL, SMTP і перевірка поштових шаблонів. Поточні стандартні шаблони використовують ConfirmationURL. Публікації, production-домену та підписаних магазинних збірок ще немає.

## Діагностика й панель — 0.4.0

«Діагностика» має два обсяги читання, окремі статуси груп, optional VIN і деталі запису. VIN із ECU можна явно підставити у форму автомобіля; він не перезаписується автоматично. Якщо VIN сканування відрізняється від обраного авто, результат лишається на екрані й очікує підтвердження збереження. Старі записи залишаються читабельними, зі статусом невідомого обсягу запитів.

«Панель показників» доступна з огляду й діагностики; «Налаштувати показники» відкриває вибір 1–8 параметрів із 20, їхній порядок та одиниці. Дані зберігаються в метричному вигляді, конвертуються лише для показу. Порожні значення не стають нулями; графіки зберігають максимум 30 циклів цього підключення в пам’яті. Поточні показники під час сканування не називаються ECU freeze frame.

Очищення кодів — окрема дія з підтвердженням, перевіркою поточних нульових RPM/швидкості та позитивного ACK ECU. Воно не видаляє історію застосунку й не вважається ремонтом. На автомобілі цю дію в сесії не виконували. Нативний застосунок потрібно перебудувати, бо змінився Swift/Kotlin модуль.

Додаткові перевірки: Kotlin JUnit — 9 тестів; однакові 9 VIN fixtures на Kotlin і Swift, 8 додаткових Swift перевірок відповіді; Swift OBDManager typecheck для iOS Simulator. Swift fixture-команда: `swiftc modules/obd/ios/VinDecoder.swift modules/obd/ios/DiagnosticResponses.swift tests/native/main.swift -o /tmp/mygarage-parser-checks` і `/tmp/mygarage-parser-checks tests/fixtures/obd-vin.json`. Kotlin JUnit-класи лежать у modules/obd/android/src/test; стандартний запуск у налаштованому Android оточенні: `cd android && ./gradlew :obd:testDebugUnitTest`. У цій сесії чисті Kotlin класи й JUnit тести також скомпільовано та виконано напряму на JDK із кешованим compiler toolchain, без APK.
