# План розвитку «Мій гараж»

Мета: всі функції DriveSpecX-RN плюс повноцінний автомобільний щоденник. Наявність пункту в плані не означає, що він уже реалізований.

## Етап 1 — робоча основа (реалізовано у цьому проєкті)

FSD, Expo, дві мови, дві теми, п’ять розділів, редагування авто, локальні дані, форми заправок і сервісу, календарні підсумки витрат, пробіг і наступний сервіс. Перенесено native BLE модуль, мапінг телеметрії й виправлений CAN decoder; додано нові UI підключення та читання кодів. Підготовлено Supabase Auth, репозиторії, SQL та RLS.

## Реалізовано додатково у 0.2.0

Підключено чистий Supabase користувача, створено чотири таблиці та RLS. На живій базі пройшла транзакційна перевірка власників без збереження тестових даних. Звіти за довільні місяці/роки, останні 30 днів/12 місяців, графік і CSV; тип пального, повний бак, ціна літра й розрахунок л/100 км; наступний сервіс за датою/пробігом, декілька термінів і статуси прострочення. Форми розділено на менші компоненти; додаткова міграція не змінює старих записів.

## Етап 2 — перевірений хмарний гараж і щоденник

Схему Supabase вже застосовано. Залишається перевірити signup/sign-in/email confirmation у застосунку з двома реальними акаунтами та синхронізувати migration history через CLI перед автоматичним db push (див. supabase/DEPLOYMENT.md). Відновлення пароля й видалення акаунту реалізовано в 0.3.0; перед релізом потрібен повний ручний цикл із поштою й телефоном. Далі — перенесення гостьових записів лише за явним вибором, фото авто через приватний Storage bucket. Додати обробку конфліктів одночасного редагування, offline outbox із видимим статусом невдалого запису, фонове оновлення даних.

Розширити реалізовані звіти: деталізація категорій сервісу, вибір довільного діапазону дат, порівняння періодів, чеки, PDF. Додати типи транспортних засобів/електрозаряджання окремим контрактом; поточні літрові розрахунки не застосовувати до кВт·год. Для інших валют — окремі суми без змішування до узгодження курсу.

Сервіс: наступна дата/пробіг і декілька термінів уже працюють. Далі — повторювані інтервали, незалежний план майбутніх робіт, запчастини, чеки, виконавець, push із дозволу користувача.

## Етап 3 — повна діагностика DriveSpecX

Фізичні BLE адаптери на iOS/Android, дозволи, вимкнений Bluetooth, розрив підключення, background/foreground, CAN і legacy відповіді. Зіставити VIN і вибране авто. Деталі сканів, статуси груп, два режими й невеликий довідник DTC реалізовано у 0.4.0. Далі — справжній ECU freeze frame, readiness, розширений довідник і повна пагінація історії. Очищення DTC із підтвердженням, перевіркою нульових RPM/швидкості та ACK реалізовано; фактичну поведінку треба перевірити на пристрої. Не виводити synthetic health% або "auto is safe" на основі відсутності кодів.

Телеметрія 0.4.0: налаштовувана панель 1–8 показників, порядок, графіки до 30 циклів, час оновлення й пропуски; далі PID-support discovery і додаткові віджети. Metric/imperial температури, швидкості й тиску перенесено. Конвертації потужності/моменту — разом із dyno/performance. Відокремлювати absolute MAP від boost та OilTemp від тиску мастила.

## Етап 4 — паритет решти функцій DriveSpecX

| Функція існуючого застосунку | Що перенести у нову архітектуру                                               |
| ---------------------------- | ----------------------------------------------------------------------------- |
| Garage / vehicle details     | Зображення, редагування, технічна конфігурація                                |
| Mods                         | Створення/редагування встановлених деталей, категорії й витрати               |
| Builds                       | Плани доробок, статуси, відсоток виконання, бюджет                            |
| Performance                  | 0–60, 0–100, 60–100 та відповідні одиниці, історія результатів                |
| Dyno                         | Потужність, момент, графіки й записи вимірювань                               |
| AI assistant                 | Контекст авто/кодів, двомовні відповіді, server-side proxy, ліміти на сервері |
| Authentication               | Google та Apple; recovery/deletion реалізовано, device QA попереду            |
| Vehicle photos               | Приватні файли, дозволи, очистка за життєвим циклом авто                      |
| Dashboard                    | Вибір авто, персональні параметри, графіки й стани без даних                  |

Модифікації/build/performance потребують власних таблиць та RLS у Supabase; старі Firebase services не копіюються як нібито робочі сервіси Supabase. Ключ AI не повинен потрапляти в EXPO_PUBLIC_* чи мобільний bundle.

## Етап 5 — готовність до App Store / Google Play

Остаточні bundle/package identifiers і branding; новий EAS project; signing; актуалізація Expo SDK окремою перевіреною міграцією. Повні фізичні device tests і release regression. Production Auth (включно з recovery та deletion), політика приватності, декларації даних/дозволів, сторінка підтримки, screenshots для обох мов, accessibility перевірка з VoiceOver/TalkBack. Перевірка схем RLS у реальному проєкті та відновлення даних. Тільки після цього — підписані збірки й публікація.

## Реалізовано додатково у 0.3.0

Повторний лист підтвердження, запит відновлення, PKCE callback з явним підтвердженням, форма нового пароля, захищене видалення власного акаунту. Supabase міграція 003 і development callback URLs налаштовані; серверні перевірки з відкатом пройшли. 28 автоматизованих тестів. Наступна продуктова задача — явне перенесення гостьового гаража до акаунту без дублікатів і втрати даних; далі приватні фото.

## Реалізовано додатково у 0.4.0

Перенесено наступний блок діагностики: VIN, режими, часткові результати, деталі історії, збережені знімки, безпечне очищення кодів, невеликий двомовний довідник. Додано 20 параметрів у налаштуваннях панелі, вибір/порядок, метричні/імперські одиниці та графіки поточного з’єднання. Покращено native VIN/відповіді ECU. Supabase міграція 004 застосована й перевірена з rollback.

За вказівкою користувача фізичні ручні тести залишено до завершення перенесення; вони не блокують наступні блоки коду. Наступний блок паритету DriveSpecX — Mods і Builds. Гостьовий імпорт, приватні фото й offline/conflict handling залишаються окремими продуктовими задачами, описаними вище.
